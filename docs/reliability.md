# 反代可靠性：候选、重试与真实失败原因

## 一次请求如何处理

DSH 私有 worker 和 Hermes 的 OpenAI 兼容 HTTP 接口使用同一套网关路由语义。请求进入后会保存本次请求的能力契约，只包含模型 ID、字节/消息/工具计数、图像标记及输出预算等元数据，不把提示词和工具结果写入使用账本。

网关复用本次目录发现得到的元数据。确定不支持本次工具、图片、上下文或输出预算的候选，会记为 `skipped`，不发送生成请求、不触发额度耗尽或供应故障冷却。未知能力保持未知；模型列表和模型显示名不是实际可用性证明。

**已提交请求的消息、工具 ID、工具结果和输出预算保持原样。** 所有已知候选都接不住时，网关明确结束；不会把最后一个候选的输出上限偷偷改成请求上限。该行为取代早期版本的末位自动夹紧策略。客户端新请求应基于当前目录的实际主供应能力设置预算，旧客户端缓存过大的预算则需刷新目录，而不是由网关静默缩水。

## 跳过、尝试、派发和请求结果

活动接口分别提供：

- `skippedCandidates`：本地决定跳过的候选数，未向上游发送生成。
- `attempts`：实际派发过生成的候选次数；一个请求可能尝试多个候选。
- `dispatches`：实际生成派发次数，包括同候选有界传输恢复。
- `upstreamFailedAttempts`：已派发但失败的候选次数。
- `requests / success / failed`：按请求关联后的终局数量，不是候选数量。

例如，一个请求跳过 14 个低容量账号，然后由一个合格账号成功完成，应该显示 1 个成功请求、14 个候选跳过、1 个实际候选尝试，而不是 14 次用户任务失败。历史未带新元数据的行保留原记录，不追改旧账本。

单条使用记录包含 `requestContract`、`candidatePlan`、`requestOutcome`、`dispatched` 和 `dispatchCount`。它们只解释网关处理过程；服务端成功不等于客户端整轮工具任务成功，也不推断官方计费是否已结算。

## 由谁负责重试

由网关在一次总期限内管理候选接力与有依据的恢复。客户端收到标记为网关已管理的终局错误后，不再把整个池从头执行一遍。DSH 的适配器及 Hermes 的独立 AI 网关插件处理这一标记，其他 Provider 保持原策略。

已取消、已交付部分结果或结果不确定的请求，不通过无条件回放制造第二次执行。长窗口限流按官方元数据报告，积分余额不代替 Token/时间窗口可用性。

Hermes 的流式错误处理还可能在外层分类之前尝试非流式探测或传输恢复。配套集成通过官方分类钩子提供网关的终局判定，并在该流式执行点尊重判定；仅配置插件而未应用对应版本的执行点适配，不视为完整重试贯通。安装前应检查实际 Hermes 源码版本，备份原件并验证其他 Provider 对照。

## 期限不是越长越好

连接、响应头、首个语义输出、持续生成空闲和整个请求有不同期限。接力共享剩余总预算，不能每换一个账号重新计时。DSH 外层预算根据模型目录的请求期限加少量交付余量，不把长路由静默压回固定上限。

SSE 心跳只表示连接存在，不表示模型有生成进度。对确实卡住的上游应有界结束；对仍在预填充或持续生成的上游，不应用错误的短空闲计时切断。

## 如何看失败原因

客户端响应带有关联 ID，以及经过白名单处理的 `relayFailure`：

```json
{
  "root": {"code": "provider_auth_rejected", "status": 401, "platform": "SAMPLE"},
  "last": {"code": "tools_not_supported", "status": 400},
  "skippedCount": 2,
  "attemptCount": 1
}
```

这说明原供应认证失败，后续候选又不支持本次工具；不能只让最后一个能力错误覆盖原认证故障。纯粹没有合格候选时仍是不可用结果，不伪装为成功。

关联 ID 用于定位网关记录，不是幂等回放凭据，也不代表上游支持重复请求去重。普通请求与工具回合保持各自身份，不用请求体指纹擅自合并用户主动重问。

## 验收层次

1. 单元及故障注入：普通/流式、工具多轮、长 UTF-8 输入、取消、400/429/5xx、目录/生成超时、部分输出隔离。
2. 客户端实际传输：DSH 适配器和 Hermes 官方分类/流式处理路径验证，确认没有隐藏的第二次生成。
3. 真实上游与整轮任务：分别在两客户端完成所选模型的工具闭环，标明实际模型、版本证据、输入规模与结果；不拿其他供应的成功代替原供应恢复。

`/health=200`、模型目录出现、余额读取和一次短答都只证明各自层面。上游整体故障、登录态过期或严格同版本没有兼容备用时，应保留准确失败与完整请求。生产稳定性和 Node 原生生命周期需要独立验收，不由测试进程强制退出或断言数量代替。
