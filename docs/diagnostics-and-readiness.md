# 请求诊断台、路由预演与接入生效检查

这三项功能在原生桌面中使用同一后端，默认只读取本机已保存状态，不提交模型生成。管理 API 仍要求 `adminKey`；公共模型 Key 和 DSH 私有 shim 不开放这些管理入口。

## 请求诊断台

从“活动洞察”的诊断工作台查看请求列表、详情和原活动时间轴。支持按时间范围、客户端来源、模型和文字筛选，选中请求可查看候选、实际派发、真实供给、最初及末次失败原因，并复制脱敏摘要。

`GET /admin/request-diagnostics` 返回 `items` 与 `coverage`。可用参数为 `requestId`、`range`（`24h/7d/30d/all`）、`source`、`model`、`search`、`limit`。指定 `requestId` 时另有 `request` 详情，未找到保持空值。扫描范围与截断提示一并展示，不把本机账本解释成全平台完整历史。

- 本地候选跳过、实际候选尝试、生成派发分别计数。
- 请求路由、实际供给平台和模型分别记录；账号使用脱敏关联引用。
- 只投影白名单元数据，不输出提示词、工具参数、工具结果、完整账号身份或凭据。
- 总耗时与已记录的首个有效输出耗时来自账本；尚未采集的连接/TLS/响应头等细分耗时保留未知，不补造数字。
- `completion.gatewayRequest` 只表示网关请求终局。`toolExecution` 与 `clientTurn` 缺少直接客户端回执时保持 `unknown`；HTTP 200、模型提出工具调用、请求内存在 tool 消息，都不单独证明客户端整轮完成。

## 路由预演

在模型路由页选择一条路由后打开“路由预演”，填写输入规模、输出预算以及工具、图像或多轮需求。结果表列出候选顺序、能力、跳过原因、冷却和保存体检的时间。预演不会启用路由、切换账号、续期认证、刷新上游目录或申请推理额度。

`POST /admin/route-preview` 支持两种输入：完整聊天对象（或 `{ "request": CHAT }`），以及以下元数据示例：

```json
{
  "routeId": "SAMPLE_ROUTE",
  "inputChars": 10000,
  "outputBudget": 4096,
  "requiresTools": true,
  "hasImages": false,
  "messageCount": 3,
  "hasToolHistory": true
}
```

元数据模式不是原始请求的完整验证。字符数仅用于保守的充分适配估计，不是分词器结果；不能证明适配时显示未知。完整模式保留原消息、工具和显式预算，不将请求裁剪后预演。当前管理请求体上限仍为 4 MiB。

候选 `state` 为 `eligible/unknown/skipped`。`eligible` 仅表示当前已知条件满足，不表示已锁定供应、目录仍新鲜或本次生成一定成功。目录缓存的新鲜度与保存的体检结果分开展示。OpenCode 当前纯文本桥对多角色、外部工具、图片及显式生成参数继续报告原有不兼容原因。

## 接入生效检查

在诊断工作台打开“接入检查”，分别查看 AI积分网关、DSH 和 Hermes 的安装、配置、磁盘同步、运行加载、模型发布及验收阶段。

`GET /admin/client-activation` 返回 `readOnly:true` 与三个客户端的 `checks`。检查限定在标准安装/profile/命名 Provider 及插件文件，不执行 `key_cmd`，不启动模型、不重启客户端、不改变配置。逐项读取有超时与大小上限；读取失败不是“未安装”或“验收通过”。

磁盘版本一致只证明版本一致；关键文件哈希一致才支持磁盘同步结论。DSH/Hermes 没有直接加载证据时显示未知或待重载，启用路由数量不等于客户端已经发布模型。真实验收也不从健康检查或目录推断。服务启动时锁定的版本与当前磁盘包分别检查，避免将刚覆盖的文件当成正在运行的新版本。

## 路由顺序与操作名称

路由目标可以可视化上移/下移，并在保存前对比原顺序与新顺序。`POST /admin/routes/SAMPLE_ROUTE/targets-order` 使用 `{ "targets": NEW_ORDER, "expectedTargets": ORIGINAL_ORDER }`：

- 仅允许现有目标及其全部字段的严格排列，不借排序删除、重复或替换目标。
- 原列表已被其他操作更改时返回 `409 configuration_changed`，要求重新加载。
- 只保存当前路由的目标顺序，不覆盖其他账号、路由或导入选择。

“导出选中模型”改为明确的取消导入/停用操作，并非文件导出；原账号 JSON/ZIP 导出独立保留。“刷新目录”与“体检已导入模型”分开，真实体检前显示范围、阶段和耗时提示。积分调用、签到、自动任务及整个账号的开关继续各自独立，以界面说明的影响范围为准。

## WB 顶部今日签到标记

每个 WB 账号卡顶部、版本与启用状态旁显示今日签到状态：官方本日记录明确为真时显示“今日已签到”，明确为假且活动有效时显示“今日未签到”。昨日数据、缺核验时间、过期缓存、核验失败或活动不可用时显示“今日签到待核验”。

标记按本机显示日期与核验时间判断，不把余额增加、任务提交成功或历史签到当成今日签到。它只显示已保存的官方结果，本身不触发签到或领取。
