# WorkBuddy 渠道校验、错误提示与接力

## 0.8.1 的构建与更新约束

WorkBuddy 适配的正式源文件是 `vendor/workbuddy/upstream.ts`，`vendor/workbuddy-core.mjs` 是构建产物。只修改生成文件会在下一次构建或更新时丢失。

本版本将已验证的系统提示词适配写入 TypeScript 源，构建后运行离线产物检查，打包前重新构建。回归测试还会在临时目录从 TypeScript 重新生成模块，验证更新链条仍保留适配。适配仅作用于 system/developer 系统文字；用户消息、历史工具结果、工具定义、模型、输出预算和原始请求对象不作裁剪。

## 11128 与普通 HTTP 400 的区别

`workbuddy_channel_rejected` 表示 WorkBuddy 的结构化错误明确包含业务码 `11128`，即渠道校验未通过。客户端显示“WorkBuddy 渠道校验未通过（11128）”，保留网关请求编号、根因以及实际派发/跳过数。错误不表示账号封禁、余额为零或普通参数错误。

HTTP 错误和 HTTP 200 流中的结构化业务错误均按供应来源归类。其他供应出现同一数字、正文引用数字、普通 400，以及认证/限流错误不按渠道拒绝处理。公开错误只传递固定类型和白名单业务码，不把原始响应、系统提示词、Token 或 Cookie 写入客户端历史。

## 接力边界

- 沿用用户已经启用的同型号接力及分区策略，不自动启用其他分区，不换模型，不删工具或压缩历史，不降低预算。
- 尚无正文、推理或工具调用等语义输出时，明确的渠道拒绝才允许选择现有合适候选；同一请求跳过已被拒绝的同一 WorkBuddy 渠道，避免逐账号重复撞同一规则。
- 国内站与国际站按实际渠道独立处理；本次请求的渠道跳过不变成账号封禁或额度耗尽，也不建立跨请求的永久禁用。
- 一旦收到语义输出，即使内容仍在网关缓冲而未发给客户端，也不因 11128 再次生成。取消、整体期限、候选能力和输出容量限制继续生效。
- 备用候选均不合适或接力已用尽时，终态保留渠道拒绝根因。DSH/Hermes 不再从客户端重复整轮网关接力。

## 验证与打包

在仓库根目录、Node.js 22.23.3 或以上运行：

```powershell
npm run check
node --test tests/workbuddy-channel-*.test.mjs
npm pack
```

`npm pack` 的 prepack 会重新构建并验证生成模块。专项测试使用合成输入和本地 mock，不需要私人账号或调用真实模型。发布包应保留 `package.json` 的版本、正式 TypeScript 源和经检查的生成模块；安装后按实际服务入口核对版本与文件，磁盘更新和驻留进程激活分别记录。

## 维护提示

上游渠道规则可能变化；本版本保证已覆盖行为的构建、错误归类与接力约束，不把既有测试当作未来上游行为的保证。再次出现错误时先记录请求编号、供应类型、结构化业务码和是否已经输出，不以无限重试或逐账号轮换代替定位。
