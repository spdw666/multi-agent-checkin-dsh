## 已定位的问题及修复

1. 旧目录仅给 GLM-5.2 调用合同，其余型号只发现不发布；现按已验证当前清单补齐，不删除型号缩小分母。
2. 旧转发缺少稳定传输会话和精确型号头，顺序前三次后出现 TM.00001041；现按当前凭据派生稳定传输会话，独立聊天仍使用不同 chat_id。签名算法和登录流程沿用原实现。
3. DSH companion 的异步 ModelInfo 查询会在首包使用通用 registry 的预算；现同时携带精确模型、声明的上下文及默认输出协商头。显式调用预算和工具/消息不改写。
4. Kimi-K3 将实际无环的共享引用报为无限递归；本地展开消除了该错误，但完整331工具仍触发上游 Schema 大小限制。产品没有删工具或放宽参数来换取通过。
5. 流内业务错误保留真实有界脱敏诊断，避免仅看到 HTTP200 或笼统 SERVER。

## Kimi-K3 后续状态

原始单函数 DAG 也会报递归错误，说明不是仅跨工具定义重名；完整展开的最大函数从57175增到154071字符后被报大小超限。未部署的等价紧凑候选缩至65118字符：82907次独立验证器差分为0差异，单函数实际编译诊断成功，但尚未完成331工具的真实DSH读取/回填/最终正文闭环。它不是本次产品发布内容，整体全型号全工具目标继续保持未完成。

## 可重复检查与资料

离线回归使用合成 SAMPLE 凭据和可注入 fetch；不需要真实登录、私有路由、聊天记录或本机绝对路径。真实客户端检查应逐型号使用同一完整工具集：读取新随机文件、确认 tool_call_id 配对、核对最终正文、核对实际供给与两次派发；普通体检绿色状态不能替代该过程。重载时先等待活动回合结束，分别确认桌面 HTTP 后台与 DSH worker 的运行版本。

- [CodeArts2API 固定协议参照](https://github.com/2951461586/CodeArts2API/blob/c11aa7bba77d148ed04dec2c6a67b74cb8732293/internal/codearts/client.go#L130-L175)：稳定传输会话与匹配型号头；协议独立实现，未复制其整套网关。
- [CodeArts Agent 官方模型说明](https://support.huaweicloud.com/usermanual-codeartsagent/codeartsagent_ug_0009.html)：区分 Agent/Q&A 模式，不以另一模式容量替代本地合同。
- [JSON Schema 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core)：本地引用及兄弟断言语义。
