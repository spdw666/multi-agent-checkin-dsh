## 新增发行内容门禁

公开脚本 [`scripts/audit-webview-release.mjs`](../scripts/audit-webview-release.mjs)在 CI 上传构建附件之前执行，配套 **42 项**合成负例/边界测试。它检查路径与清单、首次启动模板、SQLite/归档魔数、伪装扩展名、PE 字符串、外部元数据、品牌资源 hash 和诊断脱敏；实际 SQLite 被改名为 `.mjs` 后仍会拒收。测试只使用 SAMPLE 数据。

```sh
node --test tests/webview-release-audit.test.mjs
node scripts/audit-webview-release.mjs --zip RELEASE.zip --expect-sha256 SHA256 --build-info BUILD-INFO.json --report audit.json
```

CI 的未打包构建目录可使用 `--directory DIR --allow-missing-checksums`，但发布 ZIP 默认必须有完整校验清单。发行门禁、真实值交叉对照、图片人工检查和历史审计互相补充，某一项通过不替代其他项。

`BUILD-INFO.json` 的源码 SHA 描述的是**实际 Windows checkout / 编译输入字节**。Git raw blob 与 Windows 文件可能因 CRLF、UTF-8 BOM 不同：18 项输入归一后全部对应 tag，212 项可映射包内源码内容相同，另两项许可来自 NuGet SDK。该记录不是跨构建逐位相同的声明。

审计结果应只公布路径/类别/处理与证据摘要，不把命中的原始秘密或个人数据复制进 Issue、日志、发布说明或聊天。若发现需要处理的秘密，另行记录对应修复与失效处置，不靠删一个文档链接证明秘密已经失效。

## 如何核对发行原件

1. 从固定 Release 下载正确文件，而不是从使用后的工作目录重新打包。
2. 比对完整 SHA-256、附件名和大小。已公开的 ZIP digest：

   ```text
   a2693c8492622689962bdef87787e74560fa6ea1911090f8d66acd0b702cf81d
   ```

3. 解包到新目录；核对逐文件 `checksums.sha256`，并确认没有 `user-data`、个人 `config.local.json`、runtime 数据、日志、SQLite、profile、账号交换备份或 `node_modules`。
4. 检查 `core/config.first-run.json`：账号、上游、路由为空，排程与启动签到关闭；`port=0` 与独立 marker 属实例设置，不是其他安装的私有配置。
5. 查看 Node/WebView2/bootstrapper 来源、pin、签名与许可证；第三方构建路径/版权文本和作者个人运行路径分开分类。
6. 在已标明的环境验收首次运行：只观察空态、自己的配置目录、端口与生命周期，不自动登录、领取或发模型生成。

`.gitignore`、包脚本过滤、CI 通过和杀毒扫描各自有价值，但都不单独证明整个历史或所有二进制内容没有私人数据。发布后重新下载核对，和构建前扫描，属于不同证据。

## 用户自己的数据会在哪里

Web 便携版第一次运行时才生成自己的 `user-data`；目录不可写时使用专有 LocalAppData 身份目录。配置、凭据快照、后台 API 密钥、SQLite、日志、WebView profile、窗口状态和运行记忆都留在该实例使用目录。自己的账号导出物、删除/替换前备份也属于私有数据。

普通展示 DTO 与账号导出分开：日常页面不批量回传认证凭据；账号导出按用户主动选择写文件，其内容就是登录备份，不能把它当脱敏诊断包。真实账号标签、余额、日期和任务状态本身也可能暴露个人使用情况，发布截图前应独立审查。

程序按你的操作访问官方平台、模型服务、登录和依赖下载来源；“数据不随发行原件附带”不等于“程序永不联网”。源码示例使用 TOKEN/SAMPLE 等占位符，平台账号和免费资格由使用者自行准备。

## 反馈与公开贡献

可以提供：版本、公开 commit/tag、附件完整 hash、操作入口、错误码、时间区间、最小复现和经过审查的 SAMPLE 输入。

不要提供：账号导出文件、Cookie/Token/Key、完整配置/runtime、凭据或 profile、未脱敏原始聊天、完整设备标识，以及含真实账号状态的截图。新的图示优先用纯代码架构或明确标注 SAMPLE 的合成输入，不复用私人截图像素。

审计结果后续更新时保留对象、版本、证据时间和未覆盖项；当前发布检查、全 Git 历史检查、官方账号认证与真实权益结算不互相替代。
