# 运行中心与应用控制

运行中心是已有账号池、路由和诊断能力的操作入口，不替换供应商客户端，不改变原消息、工具、输出预算或模型回答。原生桌面和网页提供同一组操作。

## 软件更新检查

“刷新列表”只读取已保存结果；“联网检查版本”重新读取官方版本接口；“重试失败项”只检查上次失败的项目，单行可单独重试。检查期间显示每项进度和重试状态。

连接超时、HTTP 错误和响应格式错误分别显示。暂时性读取错误最多追加两次有退避和抖动的重试；取消不重试。失败后按连续失败次数在约 5／15／60 分钟后再次检查，非暂时性错误稍后重查；成功项目仍按每天一次检查。此机制不下载或安装软件。

本次失败时保留上次成功版本和时间，并明确标为旧结果；旧版本不冒充本次官方核验。官方来源地址和完整错误可在详情查看。国内版和国际版保持独立。

## 健康与选路

- 健康数据来自最近 24 小时、最多 5,000 条本机调用观测；显示样本数、成功率、首字中位耗时、P95 请求耗时和冷却。无样本表示未知，不等于失败或零延迟。
- 默认 `configured` 沿用原顺序；`stable` 优先已观测较稳定的候选，`fast` 优先已观测首字较快的候选，`expiry` 优先使用已核验且即将到期的权益。
- 只对本来就合格的同模型候选调整顺序；不会偷偷更换不同模型、裁剪消息或降低输出预算。能力、凭据、启用状态及官方错误仍走原有最终检查。
- 不自动发出收费的生成式健康探针。网关观测耗时不等于供应商纯生成耗时或客户端最终交付耗时。

## 每个应用使用独立密钥

在“应用密钥”中为 DSH、Hermes 等客户端创建单独的 Key，可以设置允许的网关模型 ID、每日请求上限、Token 预算和最大并发，并单独撤销。

创建时仅显示一次明文，后续列表和磁盘只保存摘要与计数；网关管理 Key 不可替代为应用 Key。原有主调用 Key 继续可用，既有客户端无需强制迁移。

Token 预算在派发前做保守预约（完整请求 UTF-8 字节上界加输出预算），完成后按供应商回报结算；未知用量保持明确的预约／未知计数，不伪装为零消费。每日计数使用 Asia/Shanghai，跨午夜的运行中请求仍占用并发名额。失败、取消、断连都释放并发；重启遗留预约有期限，并保留预算消耗。已知积分按平台原生单位分别统计，不把不同平台积分相加或折算成金额。API 的 dailyKnownCreditLimit 仅限制官方返回的 WorkBuddy 积分，对其他平台不生效；未知积分消费不冒充精确硬预算。

示例（`APP_KEY` 在本机输入，不写入公共配置或日志）：

```powershell
$headers = @{
  Authorization = 'Bearer APP_KEY'
  'Content-Type' = 'application/json'
  'X-AI-Credit-Session-Id' = 'project-session-001'
}
$body = @{model='ROUTE_ID';messages=@(@{role='user';content='Hello'})} | ConvertTo-Json -Depth 12
Invoke-RestMethod http://127.0.0.1:19421/v1/chat/completions -Method Post -Headers $headers -Body $body
```

## 会话亲和

在运行中心开启后，同一应用 Key、同一路由及同一个 `X-AI-Credit-Session-Id` 优先使用上次真正成功的候选。会话 ID 为 1–128 位 ASCII 标识（字母、数字、下划线、点、冒号、短横线），不传聊天正文。

绑定仅在完整成功后建立；账号来源变化、停用、不再符合资格或绑定过期时失效，原接力仍可处理失败。CN／AI 版本与凭据引用隔离。页面仅显示匿名会话引用及目标元数据，不保存会话内容；绑定是进程内状态，重启后重新建立，不冒充跨进程全局会话锁。

## 积分到期日历

日历使用已经读到的 WorkBuddy 官方积分包，分别展示未来 24 小时、3 天和 7 天累计到期积分、包数及账号数。超过新鲜度期限、来源不匹配、到期时间未知或不完整的结果单独标注，不混入确定总数。停用账号的已知资产仍可见，但不推荐调用。

推荐账号需余额新鲜、可调用、未封禁且不在冷却；最终调用仍以路由复核为准。日历不触发签到、余额刷新、模型生成或桌面登录切换。不同平台的元、Token 与积分不混加。

## 异常通知

通知中心汇总自动任务失败、余额／登录核验异常、更新检查失败、持续低成功率及 24 小时内到期的积分。通知持久保存最近 200 项，同一回执不会因刷新反复产生新通知；新的失败或恢复有独立状态，支持标记已读。

Windows 托盘提醒需主动开启；只提示未读且未恢复的通知，去重处理。通知只给可操作的状态，不把 `already`、`observed` 或手动领取当作新增自动奖励。原每日调度、官方任务防重复提交和回执规则保持。

## 管理接口

以下接口均要求本机管理 Bearer Key：

| 方法 | 地址 | 作用 |
|---|---|---|
| GET | `/admin/operations` | 健康、策略、到期日历、应用 Key 摘要和通知 |
| POST | `/admin/operations/settings` | 保存策略、亲和开关／时长和托盘提醒开关 |
| GET / POST | `/admin/application-keys` | 查看摘要／创建应用 Key |
| POST | `/admin/application-keys/:id/revoke` | 单独撤销 Key |
| POST | `/admin/notifications/:id/read` | 标记通知已读 |
| POST | `/admin/client-updates/check` | `{failedOnly:true}` 或 `{targetIds:["loomy"]}` 选择性检查 |
