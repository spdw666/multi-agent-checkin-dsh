**AI积分网关**把本机桌面客户端账号的登录态、每日领取、余额与模型调用收拢到一个入口。可以在 Windows 原生界面管理账号，也可以只运行 Node.js 服务，通过 CLI、管理 API 或 OpenAI 兼容客户端使用同一后端。

WB 使用独立的 **wb帐号池**：逐账号展示身份、登录状态、封禁依据、积分包、任务内容与任务状态；顶部突出显示 **积分剩余 / 总额**。其他平台继续使用“积分总览”，其中不重复展示 WorkBuddy 积分。

> 兼容名称：npm 包仍为 `dsh-ai-credit-gateway`，CLI 与 DSH Provider 仍为 `ai-credit`，历史仓库地址保持不变。Windows 正式入口为 **`AI积分网关.exe`**。

真实功能自动任务的执行链、官方组件、状态和防重复机制见 [WB 自动执行器说明](docs/WB_TASK_EXECUTORS.md)。

性能与并发一致性：见 [缓存、取消隔离与离线基准](docs/performance-and-correctness.md)。优化不修改账号、路由和排程；可用固定合成输入复测数据库、调度与余额历史热路径。

## 先找到你要做的事

| 你要做什么 | 从哪里开始 | 操作后看什么 |
|---|---|---|
| 看各平台还剩多少额度 | **积分总览**；WB 单独看 **wb帐号池** | 单位、查询时间、是否缓存，以及剩余/总额；未知不是零 |
| 今天主动签到或领奖 | 顶部 **全部账号签到**，或账号管理 **领取所选账号** | 到 **领取记录**看逐账号回执，不只看操作完成提示 |
| 只想更新余额 | 顶部 **刷新全部余额**；WB 页 **刷新积分** | 新核验时间与结果；刷新不会凭空增加积分 |
| 加入已经登录的桌面账号 | **账号管理 → 添加平台账号**，选择读取本机登录并保存，再 **读取登录态** 诊断；WB 可 **保存当前WorkBuddy账号** | 新账号已保存，主体、版本与凭据状态对应要用的账号；诊断本身不新增账号 |
| 从账号备份迁入 WB | **wb帐号池 → 导入账号** | 先预览 UID/版本/重复项，再看新增、替换、跳过回执 |
| 备份 WB 登录快照 | **wb帐号池 → 导出账号**，或每号 **更多操作 → 导出此号** | 保存到你选的文件；这与模型页的“导出”不同 |
| 把模型交给 DSH/Hermes | **模型路由 → 全部模型 / 选择导入** | 保存后回到主列表，并在调用端刷新模型列表 |
| 只测试几款模型 | 主列表勾选 **选测**，点 **测试选中模型**；未导入条目用 `scope:models` 管理 API | 普通、流式、工具和回传四项结果及失败原因；测试不自动导入 |
| 使用 OpenCode 免费模型 | [OpenCode 接入步骤](#opencode-免费模型接入) | 官方本机服务、最近普通/SSE 结果及文本桥接边界 |
| 检查官方客户端版本或打开软件 | **软件更新 → 刷新 / 立即检查**；双击或右键对应行 | 来源、最后检查时间、缓存与待重启说明；检查不安装更新 |
| 暂时不发布一款模型 | 模型页取消导入，或 **导出选中模型** | 路由从主列表和 `/v1/models` 隐藏，配置与历史保留 |
| WB 某账号不再消耗积分 | 浏览该账号，点 **停用该账号** | 显示积分调用已停用；自动签到和任务开关不变 |
| 运行 WB 已接入的真实任务 | 账号 **积分任务 → 执行可自动任务** | 后台阶段和逐项回执；最终以官方达标、已领取状态为准 |
| 下次优先使用快到期的 WB 积分 | **wb帐号池 → 轮换设置** | 先预览候选与排除原因，保存后再决定是否开启 |
| 排查请求到底用了谁 | **请求诊断台**，以及账号余额卡的调用明细 | 路由、实际供给、尝试次序、错误和计费来源 |
| 让界面退出但接口继续提供服务 | 托盘 **退出窗口，后台继续** | Node 后台仍运行；完整停止使用另一项菜单 |

模型体检、真实任务执行和正常聊天都可能使用上游额度。余额刷新、读取账本、查看活动和交换账号文件不等同于模型生成；具体平台的续期与业务查询结果仍按各自回执展示。

## 第一次使用：从登录到模型回答

已有可运行桌面版本时，从下面第 1 步开始。源码用户先完成[快速开始](#快速开始)中的安装与启动。

1. **先登录官方客户端。** 选择正确的国内/国际版。API 平台按对应入口录入 Key 或引用本机私有凭据文件，别把另一平台的登录态混到同一槽位。
2. **确认网关后台已连接。** 底部可点“启动后台”。`/health` 正常只证明服务在线，接下来还要核对账号。
3. **保存并核对账号。** 进入“账号管理”读取登录态、选中账号做服务端体检；WB 也可在“wb帐号池”添加登录或保存客户端当前账号。先确认身份和版本，再查余额。
4. **选择你真正要用的模型。** 打开“全部模型 / 选择导入”，按平台、名称、类型筛选，勾选后保存。主列表只保留已启用路由。目录出现但未测试的模型，仍是待核验。
5. **先做小范围体检。** 勾选一两条路由，点“测试选中模型”，检查四项结果。只要聊天时，可接受“聊天通过”的已知边界；要用 Agent 工具时，还要确认工具及回传。
6. **配置调用端并完成一次真实任务。** 通用客户端填写网关 `/v1` 地址、模型密钥和完整路由 ID；DSH 安装 bundle，Hermes 添加命名 Provider。先测试普通回答，再验证本地工具执行和结果回传。

日常使用无需反复导入、切号或全量测试。需要定时领取时再打开对应排程；WB 自动任务、轮换和聊天迁移各有独立开关，按你的用途开启。

## 几个容易混淆的词

| 词语 | 在本项目里指什么 |
|---|---|
| 账号 | 一个本机保存的登录主体；同平台可以保存多个 |
| 上游 / 供给 | 实际接收模型请求的平台适配器及账号 |
| 模型目录 | 平台能发现的型号清单，还没有证明每款都能调用 |
| 路由 | 调用端填写的稳定模型 ID，指向一个或多个实际供给 |
| 导入模型 / 发布模型 | 选择并启用路由，使它出现在调用端模型列表中 |
| 导出选中模型 | 此按钮的既有名称；实际取消导入并停用选中路由，不生成文件 |
| 导出账号 | 把 WB 已保存登录快照写为 JSON/ZIP 文件，不改路由发布状态 |
| 体检 / 审计 | 分别检查普通、流式、工具调用与结果回传，有可能发生真实生成 |
| 接力 | 同一请求交付前，故障或低额度时尝试同版同款兼容供给 |
| 轮换 | 提前决定后续请求或下一次 CLI 启动的优先账号 |
| 刷新 / 签到 / 任务 | 查询当前状态 / 执行领取契约 / 完成对应真实功能，三者不互相代替 |

## 产品定位与架构

### 本项目做什么

1. **管理权益**：按账号读取本机登录态、检查余额、执行已实现的真实签到或领取流程，并保留服务端回执与本机幂等账本。
2. **统一调用**：把不同上游协议映射为 `/v1/models` 与 `/v1/chat/completions`，供 DSH、Hermes、FleshOut 等客户端使用。
3. **组织账号池**：让同款模型在兼容供给间接力；WB 与非 WB 隔离，登录失败、限流、能力不足和真实额度耗尽分别处理。
4. **保留可诊断性**：目录声明、离线测试、真实调用、客户端工具闭环与云同步确认分别记录，不用一个绿色图标代替这些证据。

```text
Windows 原生桌面 ── adminKey ──┐
CLI / 本机管理 API ───────────┤
                             ▼
                       Node.js 本机服务
                    配置 / SQLite / 调度器
                             ▲
DSH / Hermes / 其他客户端 ─ apiKey ─ /v1
                             │
                    路由 / 同模型接力 / 适配器
                             │
                  本机已登录账号 / 官方 API
```

- **界面与服务分离**：WinForms 负责交互；Node 负责凭据、签到、余额、任务、模型与账本。界面重连不应取消正在进行的模型请求。
- **工具由调用端执行**：网关转换和传递 `tool_calls`，不会把一段工具调用 JSON 当成真实文件操作已完成。
- **不同计费单位分别展示**：积分、Token、现金和资源包不相加；WB 汇总只统计该池同单位的已知结果。
- **本机凭据不进配置**：配置保存文件引用；令牌、Cookie、运行密钥和数据库留在本机，不随源码分发。

### WB 日常工作流

**新账号**：添加官方登录 / 保存当前客户端账号 / 导入 JSON 或 ZIP → 核对账号身份与版本 → 刷新积分 → 选择需要发布的模型。**整理账号**：修改显示名与备注 → 按 ID/UID 搜索 → 只停用积分调用或显式删除。**多账号使用**：同版同模型池按额度故障接力；另可开启到期优先/顺序轮换，提前决定后续账号。导入、发布路由、真实模型请求与官方任务完成分别给回执，不合并为一个“成功”。

常用入口与操作区别：

| 操作 | 改变什么 | 保留什么 |
|---|---|---|
| 添加/导入账号 | 新的独立登录快照；显式替换只换同主体凭据 | 原账号、稳定 ID、路由启停、历史与其他平台 |
| 导出账号 JSON/ZIP | 将选中已保存登录数据写到用户选择路径 | 账号和路由保持原状，不执行推理或任务 |
| 停用该账号 | `inferenceEnabled:false`，暂停模型/积分调用 | 自动签到、自动任务、资料和登录态 |
| 账号管理整体停用 | `enabled:false`，退出自动调度/使用 | 账号配置与历史 |
| 自动轮换 | 后续网关请求/后续 CLI 启动的优先账号 | 已开始的生成、模型 ID、上下文与工具 |
| 模型路由“导出选中” | 取消发布选中模型路由 | 账号、登录态、路由定义与历史 |

详细对照：[workbuddy-switch 参考矩阵](docs/WB_SWITCH_COMPARISON.md)。本项目使用其格式/策略知识独立适配，完整上游许可保留；IDE 插件切号、悬浮窗、签名更新等参考项目桌面功能不自动成为本网关功能。

## 快速开始

### 环境

- Node.js **最低 22.23.3**：以 `package.json` 的 `engines.node` 为准；服务使用内置 SQLite，npm 构建使用 esbuild。**Windows 推荐配套已验证的官方 22.23.3 LTS**，不是将任意较新大版本视为已验运行时。自然退出与流清理口径见 [运行时说明](docs/runtime-reliability.md)。
- Git：拉取源码与更新。
- Windows 原生界面另需本机 C# 编译环境，由 `desktop/build.ps1` 检测。
- 使用桌面账号的平台先在官方客户端登录；各平台地区、套餐、目录与能力并不相同。

### 从源码启动后端

以 `C:\Gateway` 为自选安装目录示例，不要复制别人的私有配置与数据目录。

```powershell
git clone https://github.com/spdw666/multi-agent-checkin-dsh.git C:\Gateway
Set-Location C:\Gateway
npm ci
npm run build
node bin/ai-credit.mjs init --config C:\Gateway\config.local.json
notepad C:\Gateway\config.local.json
node bin/ai-credit.mjs doctor --config C:\Gateway\config.local.json
node bin/ai-credit.mjs serve --config C:\Gateway\config.local.json
```

首次用 `serve` 在前台看启动错误，成功会打印 `GATEWAY_READY`。另开终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:19421/health
```

确认前台运行正常后，先在 `serve` 所在终端按 **Ctrl+C** 结束前台服务，再用下面的 `start` 启动后台。同一配置只保留一个服务实例；前台尚在运行时，`start` 只会识别已有服务，不会把它变成后台进程。

```powershell
node bin/ai-credit.mjs start --config C:\Gateway\config.local.json
node bin/ai-credit.mjs stop --config C:\Gateway\config.local.json
```

Linux/macOS 可运行同一 Node 后端，使用自己的绝对路径；平台凭据读取取决于客户端与系统，WinForms 桌面不在这两个系统运行。长期服务见 [Linux 部署](docs/linux.md)。

### 常用 CLI

```powershell
node bin/ai-credit.mjs doctor --config C:\Gateway\config.local.json
node bin/ai-credit.mjs health --account ACCOUNT --config C:\Gateway\config.local.json
node bin/ai-credit.mjs claim --account ACCOUNT --task daily-checkin --config C:\Gateway\config.local.json
node bin/ai-credit.mjs models --config C:\Gateway\config.local.json
node bin/ai-credit.mjs records --config C:\Gateway\config.local.json
```

`ACCOUNT` 换成配置账号 ID。批量领取用 `POST /admin/claim` 并省略 `accountId`，不把 CLI 未实现的参数当批量开关。配置可由 `--config` 或 `AI_CREDIT_CONFIG` 指定。

### 浏览器管理页与登录后自启

原生桌面之外，CLI 也保留浏览器基础管理页，包含账号与领取、模型与路由、领取记录、配置四区。它连接同一后台，不会另建一套账号或路由；原生八页和 WB 高级任务窗口仍在 Windows 桌面使用。打开浏览器管理页前，需要服务已经启动：

```powershell
node bin/ai-credit.mjs ui --config C:\Gateway\config.local.json
```

该命令从本机数据目录读取管理密钥并打开页面。不要分享带管理状态的页面地址、完整截图或本机密钥文件。

Windows 用户可安装当前用户**登录后**启动后台的计划任务：

```powershell
node bin/ai-credit.mjs install-autostart --config C:\Gateway\config.local.json
# 取消登录后自启；不删除账号、路由或历史
node bin/ai-credit.mjs uninstall-autostart --config C:\Gateway\config.local.json
```

自启任务使用当前 Node 与配置路径，以普通当前用户身份运行；不是无人登录也运行的 Windows 系统服务。移动目录或更换 Node 后，重新核对计划任务路径。机器关机、用户未登录或后台被手动暂停时，不把计划时间当作已经领取。

## Windows 原生桌面

### 构建与启动

```powershell
Set-Location C:\Gateway
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\build.ps1
```

默认仅编译到 `desktop/dist/AI积分网关.exe`。若需要可单独放置的桌面目录，同时打包后端与指定 Node runtime：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\build.ps1 `
  -BundleCore -NodeExecutable (Get-Command node.exe).Source
```

`-OutputDirectory` 可指定输出目录，`-CoreDirectory` 可指定后端源码根目录。脚本默认定位 Windows .NET Framework 64 位 C# 编译器，找不到时查找 PATH 中的 `csc.exe`。需要先在根目录完成 `npm ci` / `npm run build`。仅编译出的 EXE 还需要可用后端与 Node；`-BundleCore` 才把 `core/` 与 `runtime/` 一起准备好，不复制个人配置/数据。程序入口为 **AI积分网关.exe**。

桌面默认配置位于 `%LOCALAPPDATA%\AiCreditGateway\config.local.json`，不一定在 EXE 旁。可用 EXE 同目录 `desktop.local.json` 的 `configFile` 或启动参数 `--config` 指定其他配置。更新和备份前先确认实际使用的文件，别只备份源码目录。

仓库只分发自有 app-logo 素材。`platform-icons/` 是可选本机图标目录，不参与编译依赖；没有平台图标时使用原生占位显示。本机已有的官方客户端图标不上传公共仓库。

### 重连与更新

页面轮询、后台进程和模型长连接是不同生命周期。短暂 GET 失败采用有界重试与退避；领取、删除、切号等写操作不因重连自动重放。手动暂停后台后，不应被自动恢复立即拉起。

升级先停止旧实例，备份实际配置与数据目录，再部署程序和后端；不要只换界面却保留不兼容 API，不要覆盖用户配置、密钥和历史。回退见[本机数据、备份与回滚](#本机数据备份与回滚)。

### 关闭窗口、托盘与后台的区别

| 操作 | 窗口与托盘 | 后台签到、任务与模型接口 |
|---|---|---|
| 点击主窗口右上角 X | 隐藏到托盘；双击托盘或“打开主窗口”恢复 | 继续运行 |
| 托盘“退出窗口，后台继续” | 关闭桌面进程及托盘 | Node 服务继续运行 |
| 底部“暂停后台” | 窗口保留，显示已暂停 | 停止后台；界面不自动拉起，之后手动点“启动后台” |
| 托盘“停止后台并退出” | 结束窗口及托盘 | 请求关闭后台；运行中的操作按各自取消/收尾规则处理 |

窗口隐藏后暂停界面轮询与动效，后台排程不依赖窗口可见。需要停止 WB 某个批次时，先用任务窗口的停止按钮；“关闭任务窗口”只结束该窗口等待。不要把暂停整个后台当作单账号停用。

## 八个页面

| 页面 | 用途 | 关键语义 |
|---|---|---|
| 积分总览 | 非 WB 平台余额、每日领取和核验 | **排除 WorkBuddy**；不同单位不相加；未知不填零 |
| 账号管理 | 平台账号、启停、登录与删除 | 稳定身份绑定，换主体明确重绑 |
| 模型路由 | 模型导入、启停、目标与接力分区 | 目录发现、体检与发布分离 |
| 领取记录 | 签到、领取、重复与失败回执 | `success`、`already`、`observed` 分开 |
| 偏好设置 | 每日排程、随机延迟与后台偏好 | 保存配置不等于官方任务已完成 |
| 请求诊断台 | 请求、上下文组成、供给尝试与原因 | 字符估算不冒充官方 Token，只观察本网关流量 |
| wb帐号池 | 身份、封禁、积分包、完整任务与会话管理 | 封禁、认证失效、停用账号仍保留展示 |
| 软件更新 | 官方客户端版本监测、启动入口与桌面快捷方式 | 区分缓存、检查失败及待重启；不下载、不安装客户端更新 |

“积分总览”排除 WB 是展示分工，不是从配置、账本或管理 API 删除 WB。管理工具需要全部平台时仍可使用原有未筛选余额接口。

### 1. 积分总览：查余额、套餐和扣费依据

登录或领取后，点顶部“刷新全部余额”。卡片显示本次能确认的余额、单位、时间和状态；失败时保留错误或缓存标识。WB 积分去第七页看，不在这里重复统计。

点击余额卡详情，可查看套餐/额度窗口、余额核验差额、本网关调用明细。不同平台返回字段不同：有的返回积分包，有的返回模型组窗口，有的只公布策略上限。查看 NVIDIA 时，要区分官方限额、本机用量与逐模型状态。

需要判断某次调用扣了多少，打开调用明细，别仅用前后余额相减。余额还会受官方客户端直接使用、领取和套餐到期影响。详细口径见[额度、用量与活动怎么看](#额度用量与活动怎么看)。

### 2. 账号管理：确认登录主体与领取规则

先选中账号，再按目的操作：

- **读取登录态**检查本机凭据来源；**服务端体检**检查所选账号的官方状态，两者和模型生成是不同检查。
- **领取所选账号**运行该账号已启用的领取任务；未配置任务时会给出提示。批量入口是顶部“全部账号签到”。
- **添加平台账号**选择平台、版本、账号 ID、名称及凭据来源。WB 多账号通常直接用“保存当前WorkBuddy账号”或 WB 页官方登录入口。
- **编辑账号**维护这个槽位；**启用 / 停用整个账号**控制整个账号参与调度和使用。若只想暂停 WB 积分调用，使用 WB 页的独立按钮。
- **删除账号**会清理引用并保留私密回滚备份，聊天与历史保留。只是暂时不用时，先选停用。

操作后核对下方结果与主体。更换官方登录主体时要明确重绑；修改显示名称不会把一个主体变成另一个主体。

### 3. 模型路由：从发现到发布，再按需要体检

主列表只显示启用路由。首次添加或找回停用项，按这个顺序操作：

1. 点 **全部模型 / 选择导入**。
2. 按平台、名称或模型 ID 搜索，再用类型筛选区分聊天、向量、图像等。非聊天目录项仍会保留类型与可导入状态。
3. 逐项勾选，或点 **勾选筛选结果 / 取消筛选结果**。筛选只是改变视野；保存只提交本次真正改动的条目。
4. 点 **保存导入选择**，查看回执。勾选代表启用发布，取消勾选代表取消导入并停用；原配置和体检历史保留。
5. 回到主列表，核对路由 ID、状态与优先级上游。客户端使用这里的完整 ID，不是随意填写官方展示名。

日常测试按需要选一种：

| 按钮 | 做什么 | 适合什么时候用 |
|---|---|---|
| 测试选中模型 | 只测试“选测”列勾选的启用路由 | 登录变化、单款故障或少量模型验收 |
| 刷新目录 | 更新模型目录，不运行生成体检 | 查目录变化或刚保存的导入选择 |
| 体检已导入模型 | 确认范围与阶段后，对已导入模型做四阶段体检 | 复核正在使用的模型；执行前查看耗时提示 |
| 测试全部模型 | 遍历发现的模型进行体检 | 有明确全目录核验需求时，先考虑账号额度与耗时 |
| 重启 DSH | 退出并重开 DSH，让其重新加载代码/模型 | 已保存导入而 DSH 仍载旧模块；先结束 DSH 内的运行任务 |

体检状态可为全部通过、部分通过、待复测、当前通道未提供或失败。悬停状态列查看原因和时间。普通回答通过不代表工具结果回传也通过；体检为被测供给独立记录，接力成功不替代原供给通过。

**目录里还没导入的型号也能定向核验**：管理 API 接受 `{"scope":"models","items":[{"upstreamId":"SAMPLE","model":"SAMPLE"}]}`，按上游与模型精确选择，不先启用路由、不自动更改导入选择。主列表的“测试选中模型”仍按已启用 `routeIds` 选择。执行中两种精确选择均返回 `409 audit_in_progress`，避免测试集合被悄悄换掉；完整校验、轮询与历史保留规则见 [模型体检 API](docs/api.md#7-模型体检post-adminmodel-tests)。

目录中的 **“对话已验证”**（`chat_verified`）表示最近保存记录的普通与 SSE 均通过、工具未声明；它不是“四项全部通过”，也不是图片或外部工具能力证明。失败阶段、最新时间与先前尝试仍可查，历史通过不保证当前可用。

要调整优先级，选路由后打开可视化顺序编辑，使用上移 / 下移排列目标，核对保存前后预览再提交，前面的目标先尝试。高级 JSON 编辑仍可使用；旧窗口目标列表已变化时，顺序保存返回冲突并要求重新加载。表格按列排序只是查看方式，不是保存后的供给优先级；可视化编辑提供独立的上移 / 下移按钮。WB 的 **WorkBuddy账号池** 入口另管理该路由的成员与优先账号：池里保存的成员顺序就是优先次序，保存后仍会继续接纳同版新账号，不需要每加一个号就回来重勾一遍。唯一例外是把整个池关掉，那是有意停用，不会被自动打开。

**取消导入 / 停用所选路由**（原“导出选中模型”）的确认框会列出要停用的路由。此处“导出”不是下载文件，也不会删除账号、登录态、目标或历史。恢复时在全部模型窗口重新勾选。账号 JSON/ZIP 备份请到 WB 页操作。

### 4. 领取记录：确认每个账号发生了什么

点“刷新领取记录”，按时间、平台/账号、任务和结果找对应记录；双击一行打开完整领取详情。`already` 表示已经做过，`observed` 表示观察到官方自动额度，二者都不表示又加了一次积分。

一次批量请求可能同时包含成功、已完成、待操作和失败。看逐项原因、官方确认字段和重新查询后的状态；顶层 HTTP 成功与窗口结束不替代账号级回执。

### 5. 偏好设置：安排自动领取，保留高级配置

打开 **定时与平台设置**，设置每日自动领取、显示时区下的执行时间、随机延迟上限，以及哪些账号整体启用，然后保存。随机延迟表示在计划时间后分散执行，不是保证整点已经领完；机器关机时服务不会运行。

**高级配置**切换到 JSON 编辑器，适合维护窗口、超时、路由等完整字段。点“保存配置”后按提示处理需要重启的监听设置；“重新载入”读取已保存版本，尚未保存的编辑要先保留。WB 自动接任务、轮换与自动迁移不由“每日自动领取”一个开关统一控制。

### 6. 请求诊断台：定位一次请求的供给与接力原因

原“活动洞察”已整合进左侧“请求诊断台”，领取与活动时间轴继续保留为独立页签。

选择 **近 24 小时、近 7 天、近 30 天或累计全部**，按来源、模型和文字筛选，再打开时间轴中的记录。可以看到本网关的请求终局、实际尝试、候选跳过、生成派发、已返回 Token、输入组成估算与接力原因。“累计全部”仍受本机实际保存范围和接口扫描上限约束，查看覆盖提示，不当作全平台全历史。

Token 使用 **K/M/B/T** 短级制（如 `540.6M`）；字符数、请求数与 Token 各有口径，不因为格式缩短而混成同一种数据。`skippedCandidates` 是本地候选跳过，`attempts` 是实际候选尝试，`dispatches` 包含有界传输恢复的实际派发；跳过候选不计成真实上游失败。

例如客户端仍显示原模型 ID，但实际由另一个同款账号回答，可以在这里核对供给变化。活动记录中的工具名和文件操作分类说明请求携带了什么，不证明客户端真正执行过工具。本网关之外的调用不在这里。

### 7. wb帐号池：一号一页，管理积分与任务

顶部“刷新全部余额”会同时核验 WB 官方今日签到状态，并同步账号卡上的“今日已签到 / 今日未签到 / 今日签到待核验”。它只查询，不代替“全部账号签到”；回执显示核验数量，待核验项显示具体原因。

用账号下拉、名称/账号 ID/UID 搜索，或“首 / 上 / 下 / 末”翻页。浏览账号不会切换官方客户端，也不会改变下次模型供给。刷新会尽量保留正在读的账号与资料位置。

宽窗口分栏展示身份资料、登录与封禁、积分包和任务；窄窗口用资料页签。长内容通过“资料 N/M”继续翻看，不需要把十几个账号挤在同一长列表。底部保留切换、积分任务、启停、删除及更多操作。

先查看“积分剩余 / 总额”和数据时间，再操作具体账号。顶部“模型”可展开 WB 聚合型号；查看型号数量不等于每个账号都已通过该型号生成。详细操作见下节。

### 8. 软件更新：查版本、打开客户端、保留状态来源

进入 **软件更新**，先看“最后检查”与“来源”。**刷新**只读取后端保存的上次报告；**立即检查**才向对应官方来源重新核对。同一服务已有检查运行时共用该次任务，不并发重复启动。自动检查默认每 24 小时一次，周期可配置；后台关闭期间不会补造已执行记录。

逐行区分“有新版本”“已是最新”“本地较新”“未检测到”“检查失败”与停用状态。客户端下载已就绪但尚未重启时，说明列标记 **已下载就绪，重启客户端后生效**（`pendingRestart:true`）；这不是当前进程已经运行新版本的证明。旧缓存、读取到的新版本目录与运行中进程各有自己的时间点。

双击行或点 **打开所选** 启动对应客户端；右键可打开安装目录、官网、查看检测详情、复制路径、创建单个/全部桌面快捷方式。快捷方式只是入口，不安装软件。监测本身 **不下载、不安装** 更新，也不结束正在进行的客户端任务；收到新版本后按官方客户端流程升级。已实现接口与后续自动安装调研见 [客户端版本监测](docs/client-updates.md)。

## wb帐号池详解

完整字段与管理协议见 [WB 帐号池手册](docs/wb-account-pool.md)。

### 汇总与账号卡

- 顶部独立区域以大字号展示池 **积分剩余 / 总额（总资产）**，另列 **可调用积分剩余 / 总额**、账号启用、积分调用启停与封禁数量。仅暂停积分调用的账号仍有已保存资产，但不计入可调用资产；两种口径分开读。
- 每账号单独一张卡；停用、认证拒绝或封禁账号不因过滤而消失。
- 卡片给身份、状态、积分、最近核验与操作入口，账号详情完整展开更多字段。
- 相同 WB 模型按精确型号只展示一次，不按账号重复铺开。
- 部分余额未知时写“已知积分剩余 / 总额”，不把未知账号当零纳入汇总。

### 身份与登录信息

| 字段 | 含义 |
|---|---|
| 账号 ID / `accountId` | 网关配置槽位，用于 API 与引用 |
| UID / `uid` | 上游主体标识，缺失保留未知 |
| 用户 ID / `userId` | 上游用户 ID，是否与 UID 相同以实际数据为准 |
| 昵称、用户名、邮箱、域/版本 | 已返回资料及国内/国际版归属 |
| 凭据状态与有效期 | Access/Refresh 状态、有效期与来源；**不展示令牌值** |
| 核验时间与来源 | 官方结果、缓存或人工本机标记分别说明 |

“添加登录”打开官方授权，国内与国际版分别处理。“保存客户端当前账号”捕获官方客户端当前登录并保存独立快照；同主体再次保存时合并，不无限产生重复账号。

多账号常驻指保存多个独立登录快照，不代表一个官方登录文件同时承载多个主体。后续切换复用保存状态；官方撤销、过期或策略变化按实际结果提示新登录。

### 封禁、认证拒绝与删除

- **已封禁**：有官方明确封禁/blocked 证据，或用户主动做了本地封禁标记；详情保留来源与原因。
- **认证拒绝 / `auth_rejected`**：会话撤销、登录失效或凭据被拒；HTTP 401/403 单独出现不等于官方封禁。
- **未知**：本次查询证据不足；保留最近成功数据与失败原因，不猜测为正常或封禁。
- **手动标记封禁**：本机整理功能，可清除；标记后退出 WB 接力候选，不自动删聊天。
- **停用该账号 / 启用该账号**：每个 WB 账号都有独立按钮，仅暂停该账号的积分与模型调用；账号资料、登录态、自动签到和自动任务继续保留。停用后不会加入模型候选或自动切号；再次启用恢复参与。该开关对应 `accounts[].inferenceEnabled`，与停用整个账号的 `enabled` 不同。
- **删除账号**：确认后清理账号、上游、池与失效路由引用；保留聊天、历史及私密回滚备份，与“停用”不同。

核对账号 ID、UID 与封禁来源后再删除。封禁卡保留是为了识别整理，不让它继续参与调用。

### 积分与积分包

详情包含**官方该查询范围返回的全部积分包**，保留其中已耗尽/过期行：包 ID、名称、编码、原始总额、剩余、已用、创建/到期/刷新时间及状态，以实际上游字段为准。查询起点为 `2000-01-01`，保留官方协议状态筛选 `[0,3]`；`queryScope` 返回起止时间和状态范围，`complete` 只代表此范围分页齐全，不保证任意状态的全部历史均可获取。

“总额”是当前官方积分包/余额体系的可核验总额，不是历史累计充值或每天承诺发放量；缺失显示待获取。最近成功、最近失败、缓存时间与错误码同时保留，帮助区分“还有积分却用不了”的具体层次。

正余额不保证任意模型、地区、套餐或工具均可用。工具不兼容、上下文超限、限流、认证与真实耗尽分别记录，不把所有错误都归为积分不足。

### 任务内容、状态与自动任务

完整任务列表给出 ID/编码、标题、说明、类型、适用端、目标与当前进度、积分/Buddy 等奖励、接受/达标/领取/锁定状态、查询时间和最近执行回执。

当前真实自动流程覆盖：

1. 查询官方任务，接受可接受任务。
2. 执行已实现的真实每日签到。
3. 领取服务端已达标且可领取任务的奖励。
4. 重新查询任务/余额，核对结果并持久去重。

**后台已接入真实功能执行器：对话、技能、专家、画布、外观、资料库与本地自动化按各自入口执行，并回查官方任务进度。** 首次对话前置任务优先处理；应用授权、订阅等待时间、资料正文与业务组件等条件未就绪时保留具体状态。完整流程、幂等规则与组件要求见 [WB 自动执行器说明](docs/WB_TASK_EXECUTORS.md)。只有官方查询确认达标才领取，只有再查 `claimed` 才显示已领取。没有执行器的任务继续显示 `manual_action_required`；已接入但条件未就绪的任务返回具体等待原因。

界面中的 **自动接任务** 是周期执行开关，后台约每 30 分钟检查，同账号互斥，默认关闭。它与每日签到排程、账号积分调用及自动轮换分开保存。关闭后停止后续自动流程；查询、接受、执行与领取分别有状态，以官方回查为准。

WB 真实任务执行器使用共享 SQLite 租约，桌面核心与 DSH 同时触发同一账号、任务时仅一个进程执行；丢租后停止后续动作，已提交但结果不确定的操作保留待核验，不重复生成。

### 积分任务窗口：接受、执行、领奖分开操作

单号入口是账号底部 **积分任务**。全号入口在 **账号池操作 → 全部接受任务 / 执行可自动任务**；这两个入口打开统一任务窗口，进入后再选择具体操作，不把打开窗口当成已经执行。

| 窗口操作 | 实际用途 | 结果怎么看 |
|---|---|---|
| 全部接受 / 单项接受任务 | 按对应操作接受任务 | 接受成功不代表功能已完成或可以领奖 |
| 执行可自动任务 / 单项真实执行 | 运行已有执行器的真实功能，处理前置条件并回查 | 看执行回执，再看官方 `current / target`；条件不足保留原因 |
| 领取已达标奖励 / 单项领取奖励 | 领取官方已达标、可领取的奖励 | 回查 `claimed`，不只看请求已提交 |
| 重新查询 | 向官方更新任务状态 | 不运行模型、不重新创建资源，也不等于重做任务 |

执行会立即建立后台作业，窗口持续显示当前账号、任务代码、查询/接受/真实执行/核验/领奖阶段、已处理数量与耗时。批量执行优先处理可领取奖励、前置任务和有真实执行器的工作；纯手工任务或仅等待外部条件的条目保留相应状态。不要把“已处理 N 项”读成“到账 N 项”。

| 你想做什么 | 应用哪个操作 | 后续行为 |
|---|---|---|
| 暂时离开任务窗口 | **关闭** | 只结束本窗口等待；后台保留，重开可接管仍在运行的作业 |
| 不再执行剩余任务 | **停止后续任务**；全号作业显示 **停止整个批次** | 发出停止请求，等待当前已提交动作确认，随后才显示终态 |
| 断线后找回进度 | **重新连接（只读）**，或等待自动查询恢复 | 保留作业 ID 与旧列表，只查询，不重发执行 POST |

停止整个批次会影响该批次所有账号，不只是当前浏览账号。“正在停止”说明尚有在途动作待确认，不表示锁已释放。已领取回执和 `submitted / pending` 记录不会因关闭、取消或超时被清空。

管理执行作业默认 180 秒后停止安排新动作；查询作业默认 30 秒。外部服务已接收的动作仍需确认，预算不是保证所有服务在此时刻返回。状态可能是完成、取消、超时或失败；完成也只说明该次作业收尾，待核验任务仍待核验。

服务重启后，内存中的作业句柄可能已经不存在。先重新查询官方任务和持久回执，再决定下一次操作；找不到旧作业不是重新执行已提交动作的理由。完整行为和接口见 [WB 自动任务执行与取消说明](docs/WB_TASK_EXECUTION.md)。

### 切号与聊天迁移

- **切换此号**：写官方客户端登录文件并切网关后续请求的池偏好，正在输出的请求不迁移。
- **只切网关**：API 的 `switchClient:false` 只改后续请求，不写客户端登录文件。
- **一键合并聊天**：把已保存账号的本机可读 JSONL/SQLite 会话以新 ID 加法复制到目标账号，保留来源和幂等映射。
- **切号自动迁移聊天**：开启后在切号前执行同样的本机复制；默认关闭。

先关闭 WorkBuddy，再切换/迁移。写入前备份与校验，失败恢复客户端登录和网关选择，不强行关闭正在执行的用户任务。

`cloudSyncConfirmed:false` 表示只完成本机处理，云端归属和同步需官方客户端下次启动确认。源会话保留；结构未适配或正文不全时返回待处理状态，不用调用账本冒充聊天正文。

界面开关名为 **自动迁移聊天**。首次迁移可先手动运行并核对目标会话，再决定是否开启；仅浏览另一账号页或给账号改备注不会触发迁移。

## 账号导入、导出与整理

旧版仅保存 Access Token 的账号也支持三种格式导出与重新导入；缺失的 Refresh Token 保持为空，不伪造续期能力。预览会标注访问态账号，到期后需要重新登录。

完整格式与 API 见 [WB 账号交换手册](docs/WB_ACCOUNT_TRANSFER.md)。WB 帐号池顶部固定有“导入账号”“导出账号”“轮换设置”，每号“更多操作”有“修改名称 / 备注”“导出此号”；原管理入口继续处理添加登录、保存当前客户端和本地显示名/备注，保持原来的身份、积分、任务与会话管理。

### 导入的操作顺序

1. 选择一个或多个 `.json` / `.zip`；先做只读预览。
2. 核对国内/国际版、稳定 UID、有效期、格式问题与重复项。
3. 选择导入条目，决定“跳过已有”还是“替换已有登录态”，再提交。
4. 查看新增、替换、跳过及逐项回执；之后按需刷新身份和积分。

支持附件类 `account` / `auth` JSON（单对象、对象数组或带 `schemaVersion:1` 的 `workbuddy-auths` 包），以及 workbuddy-switch 原始明文扁平数组；ZIP 可装多个账号 JSON。预览不返回 token，也不执行登录续期、签到或生成。JSON 中的昵称不是网关稳定 ID，文件名也不作为身份依据。

```json
{
  "account": {"uid":"SAMPLE_UID","enterpriseId":"SAMPLE_ENTERPRISE","nickname":"SAMPLE 工作号"},
  "auth": {"accessToken":"SAMPLE_ACCESS_TOKEN","refreshToken":"SAMPLE_REFRESH_TOKEN","expiresAt":1893456000000,"domain":"www.workbuddy.cn"},
  "gateway": {"label":"SAMPLE 国内号","notes":"SAMPLE 本地备注","inferenceEnabled":true}
}
```

身份按**版本 + UID**去重，默认跳过已有；显式替换只更新对应主体的已保存凭据，不覆盖原账号 ID、显示名、备注、整体启用、积分调用开关、任务和路由策略。导入的账号会自动加入所有开启中的同版账号池，明确关闭的池与停用路由保持原样。新增账号按保存回执建立，不用文件内任意路径决定本机落盘位置。

### 导出与本地整理

导出选择当前浏览账号、全部或明确多选账号，保存为兼容 JSON、逐账号 ZIP 或 workbuddy-switch JSON（`switch-json`）；格式与导入相对应，包含实际登录数据，而日常 summary/details 仍隐藏 token。把导出物留在本机私密备份目录；公开仓库只包含 SAMPLE 格式示例，不包含个人账号包、账号清单、密钥或压缩包。

显示名与备注仅影响本机识别，不修改官方 UID、登录地区或路由 ID。备注空串表示清空；账号详情继续显示身份、登录期限、封禁依据、积分包与任务。预览、保存、官方认证有效与真实推理是不同验收步骤，不把成功解析文件描述为模型已经可用。

选择格式时可按用途决定：

| 格式 | 适合什么场景 | 重新导入时 |
|---|---|---|
| 兼容 JSON | 少量账号交换，直接检查 `account / auth / gateway` 结构 | 可识别身份、登录态与本网关名称/备注字段 |
| ZIP | 多账号备份，逐账号 JSON 放在同一包 | 先预览包内有效项，再选要提交的账号 |
| workbuddy-switch JSON | 与参考项目的明文扁平数组互通 | 按 UID 与 CN/AI 归属识别，不沿用外部 ID 覆盖本网关槽位 |

实际操作：先选当前账号、全部或明确多选，再选格式与保存位置。保存后可用“导入账号”打开该文件做只读预览，核对账号数量和版本，随后关闭预览即可；无需为了验证文件而再次提交。导出只读取已保存快照，不为备份额外续期。

想整理昵称时，在该账号的 **更多操作 → 修改名称 / 备注** 中保存。适合标记工作号、备用号等本机用途；对外路由和官方身份仍保持原样。把账号移出调用候选用“停用该账号”，把模型移出发布列表到模型页操作，两者不要混用。

### 管理接口速查

| 接口 | 用途 |
|---|---|
| `POST /admin/workbuddy/accounts/import/preview` | 只读解析与去重预览 |
| `POST /admin/workbuddy/accounts/import/commit` | 按选择和策略提交 |
| `POST /admin/workbuddy/accounts/export` | 返回所选账号 JSON/ZIP 的 base64 内容 |
| `POST /admin/workbuddy/accounts/ACCOUNT/profile` | 保存显示名和备注 |
| `POST /admin/workbuddy/accounts/ACCOUNT/inference` | 仅暂停/恢复积分调用 |

全部使用 `adminKey`。普通管理 HTTP 请求为 4 MiB；账号导入入口为 base64 / JSON 转义提供 16 MiB 包装正文上限，解码后的原始文件合计仍为 4 MiB，另有单 JSON、账号与解压限制，见完整手册。导出响应含登录数据，客户端直接保存文件，不把响应正文写入反馈日志。

## 账号自动轮换

轮换默认关闭，在 [WB 轮换手册](docs/WB_ROTATION.md) 中配置目标、策略、频率、冷却、紧迫窗口、差异阈值和最小剩余积分。设置、预览、实际评估与提交回执分别展示。

| 选择 | 含义 |
|---|---|
| 到期优先 `expiry` | 有效包中剩余积分的最早到期更紧迫者优先 |
| 顺序轮换 `round_robin` | 在有效候选中按稳定顺序前进 |
| 网关 `gateway` | 只改同版同型号 WB 池下一请求偏好 |
| CodeBuddy CLI `codebuddy-cli` | 为空闲 CLI 的后续启动准备身份 |
| 两者 `both` | 两个目标分别核对并报告结果 |

整体停用、暂停积分调用、封禁、凭据/余额不满足条件、过期或未知的账号退出轮换候选。冷却和到期差异门槛用于避免抖动，不跨国内/国际版或型号替换。网关更新后不打断已经开始的生成，不重放工具，不改模型 ID/输入历史/预算。

CLI 检测到心跳新鲜的会话或明确运行进程时推迟，不关闭用户 CLI 或重启客户端。配置写入前保留原件，地区、已有 helper/环境覆盖与凭据条件分别核对；运行中进程仍持有自己的旧 token，写盘不当成该进程实时换号。

自动轮换不等于故障接力：前者按策略选择**下一次**，后者在同一请求交付前按明确故障分类选择兼容备用；两者都遵守账号积分开关。自动签到和真实任务有独立开关/幂等账本，不随轮换停止。

首次配置时，先保持开关关闭，选版本、目标与策略并保存；点“预览候选”检查被选和被排除账号，再按需点“立即评估”。立即评估使用已保存策略尝试提交，不发模型生成，也不会自动把轮换开关打开。`both` 的两个目标可能一个成功、一个推迟，要分别读回执。开启周期轮换后，可随时关闭，账号及历史保留。

```json
{"enabled":false,"target":"gateway","strategy":"expiry","intervalMinutes":5,"cooldownMinutes":120,"minUrgencyHours":72,"minRemainingCredits":0,"minGapHours":6,"edition":"cn"}
```

`GET /admin/workbuddy/rotation` 返回设置、状态与预览；`POST` 同路径保存平铺设置；`POST /admin/workbuddy/rotation/evaluate` 默认 `{"dryRun":true}` 只预览，`dryRun:false` 才尝试按策略提交。开关开启与实际切换成功分别检查，不用 HTTP 200 代替逐目标回执。

## 同模型自动接力

```json
{
  "modelRelay": {
    "enabled": true,
    "reservePercent": 10,
    "reserveCredits": 100,
    "partitions": { "workbuddy": true, "other": true }
  }
}
```

- **WB 分区**：WB 模型只接 WB 账号。
- **其他分区**：非 WB 供应之间按同款同版本接力，排除 WB。
- 全局开关、分区开关与单路由 `relay:false` 分别生效。
- 精确型号/版本匹配，Flash、Pro 和其他版本不互换。
- 保留客户端模型 ID、消息历史、工具定义/回执和输出预算，不删历史制造成功。
- 未知余额不填零，积分阈值不与现金比较；停用账号、封禁账号与停用路由不自动恢复。

额度低/耗尽、限流、认证拒绝、目录缺失和通道故障分别分类。候选需满足实际上下文、工具、图片与输出能力；能力不兼容不应写成硬额度耗尽。主供应能力广播与备用筛选分开，备用窗口较小不应压低主供应声明。

直接 SSE 已交付内容后不重放请求。接力模式采用有界完整响应缓冲，所以首批可见输出可能晚于上游首包；正文、推理和工具增量刷新进度计时。取消优先，已交付后不重放。

**单一重试所有权**：网关在本次总期限内管理候选接力与有依据的恢复；配套 DSH/Hermes 适配收到 `gatewayManagedRetry` 标记的终局错误后，不再从头执行整个池。Hermes 还需核对其实际流式执行点适配版本，单填 Provider 配置不代替该项集成。`relayFailure.root` 保留原供给 typed 根因，`last`、`skippedCount` 与 `attemptCount` 说明后续经过；后备容量错误不覆盖原认证、限流或上游故障。HTTP 429 / `6004` 长窗口限流与积分余额分开。

活动详情将候选跳过、真实派发、传输恢复与最终请求结果分开显示，不用“跳过了多个候选”冒充“上游失败了多次”。见 [可靠性契约](docs/reliability.md)、[接力说明](docs/model-relay.md) 与 [API 契约](docs/api.md)。

见 [平台登录态](docs/desktop-platforms.md)、[适配归属](docs/provider-attributions.md) 与 [免费平台](docs/free-providers.md)。

### 免费平台入口：直接填 Key，再选可导入模型

在 **模型路由 → 免费平台入口** 选择平台和本机账号 ID，填写默认遮挡的 API Key；需要时可切换显示/隐藏。Cloudflare 等平台还要填写对应附加字段，例如 Account ID。现有旧版私有 JSON 文件引用继续兼容，不需要把已经正常工作的账号重新添加一次。

提交时会核对本次目录和选择的模型，保存账号隔离的私有凭据文件，普通配置只保留引用。然后检查返回状态：Key 已录入、目录验证通过、真实聊天成功是三个不同结果。鉴权拒绝、网络失败或缺少凭据的账号保留待配置/停用状态，不显示为已连通。

“免费平台”清单说明已有注册适配、接入条件与来源，不承诺你已获得当前免费资格，也不代表每个平台都有自动签到。先看所选平台说明、额度单位和模型目录，再决定是否导入；不接收任意第三方中转站 URL。详见 [直接 API Key 录入](docs/free-provider-key.md)。

## OpenCode 免费模型接入

OpenCode 走 **已安装的官方 CLI / 本机服务**，不是把桌面 OAuth 令牌直接发往公共免费推理 URL。网关读取官方服务状态并验证认证后的本机 API；服务未就绪时调用官方 `service start`，重新发现端口后再调用。首次官方登录仍需在 OpenCode 完成。免费目录从官方本机服务实时读取，仅选择 `providerID:opencode` 的 `-free` 条目，模型下线或改名按本轮目录处理。

1. **安装并登录 OpenCode 官方桌面版。** 保留其登录数据库与本机服务配置；当前自动冷启动使用 Windows 标准安装位置的 `opencode-cli.exe`。
2. **保存 OpenCode 账号与上游。** 使用 `opencode` 类型和本机回环地址，凭据读取本机登录态；字段片段与路径含义见 [详细接入文档](docs/opencode.md)。
3. **打开全部模型目录，先核验再按需导入。** 目录出现、余额有值和模型调用成功是不同结果。未导入模型可用 `scope:models` 精确测试，不为体检擅自改变导入开关。
4. **普通与 SSE 都看最新记录。** OpenCode 每个体检阶段有界 120 秒；超时或上游错误保留具体阶段和原因。“对话已验证”只代表普通 + SSE 通过且工具未声明。
5. **客户端从最小纯文本请求开始。** 当前桥接只接单条 `user` 字符串消息；不要附显式输出预算、采样参数或外部工具/图片。需要完整历史、工具或预算的原始请求保持原样，由兼容同款供应处理或返回 typed 不兼容结果，不静默删字段制造成功。

OpenCode 当前声明 `tools:false`、`multimodal:false`，不把官方 Agent 自带工具等同于调用端工具透传。SSE 是官方完整回答组装后再映射为单块输出及 `[DONE]`，不是逐 Token 原生直通；等待首块要同时核对客户端与网关总期限。

**可选专用连接**：上游可通过 `networkProfile` 引用本机私有配置，按需启动独立连接进程与独立官方服务；它不改变用户全局代理、官方共享服务配置或其他客户端网络。未设置时沿用默认官方服务发现路径，不把专用连接当作默认必装组件。凭据、节点配置与完整控制口令只留本机；示例和错误分层见 [OpenCode 免费文本桥](docs/opencode.md)。

免费请求剩余数是本机数据库用量结合社区日上限估算，**不是官方实时剩余 API**；Zen 付费余额单独展示。官方免费资格、限流和可用性以实际回执为准，不把估算次数当成成功承诺。

## OpenAI 兼容客户端接入

| 字段 | 值 |
|---|---|
| Base URL | `http://127.0.0.1:19421/v1`，包含 `/v1` |
| API Key | 本机 `api-keys.json` 的 `apiKey` |
| Model | `/v1/models` 返回的启用路由 ID，含斜杠原样填写 |

`TOKEN` 是占位符，实际密钥从本机读取，不提交源码/反馈日志。

```powershell
$Headers = @{ Authorization = 'Bearer TOKEN' }
Invoke-RestMethod 'http://127.0.0.1:19421/v1/models' -Headers $Headers
$Body = @{
  model = 'UPSTREAM/MODEL'

  stream = $false

Invoke-RestMethod 'http://127.0.0.1:19421/v1/chat/completions' `
  -Method Post -Headers $Headers -ContentType 'application/json' -Body $Body
```

换成真实路由。模型调用用 `apiKey`，管理面用 `adminKey`，二者不互换。验证顺序：健康 → 目录 → 普通请求 → SSE → 工具请求/结果回传 → 客户端真实任务。目录可见或“测试连接”成功不等于工具闭环。

这里的兼容入口以 Chat Completions 为准。目录中的向量、图像等类型不代表统一实现了对应生成端点，也不把 `/v1/responses` 当作 `/v1/chat/completions` 的同义地址。客户端应选择与实际接口一致的模式。

FleshOut 的托管同步脚本用于维护已有托管行，默认只预览，显式 `--apply` 加上预览的指纹才提交。它不新增模型、不修改非托管模型或写作数据；修正输出预算和显式清理过时托管项，与在客户端手工新增连接是不同操作。

## 上下文、工具、推理与超时

保留消息历史、工具 schema、调用 ID/回执、客户端模型 ID 与显式输出预算。能力不匹配时给具体错误或跳过候选，不静默删工具/历史/输出预算。声明窗口、实际输入 Token、请求体字节与最大输出 Token 是不同指标。

### 工具闭环

1. 客户端发送工具定义与消息。
2. 模型返回结构化 `tool_calls`。
3. 客户端实际执行工具。
4. 客户端以原 `tool_call_id` 回传结果。
5. 模型依据结果完成回答。

五步完成才算闭环。请求诊断台的“携带工具/文件上下文”不冒充已执行操作。

### 接力时，思考强度怎么处理

“模型会推理”和“用户能选推理档位”是两回事。发生同模型换供给时，网关按实际目标声明转换控制，不把所有平台都强行写成 `max`：

| 来源与目标 | 处理方式 |
|---|---|
| 来源选了强度，目标没有可选档位 | 移除目标不支持的控制字段，由该目标自身推理行为处理 |
| 来源无可选档位，目标有档位 | 取目标实际声明的最高档；最高名称可能是 `high` 或 `xhigh`，不一定是 `max` |
| 两边都有档位 | 尽量保留合法显式意图，按目标声明映射；上限以目标真实能力为准 |
| 目标只声明思考开关，或能力未知 | 按真实开关处理，或不添加未声明参数；不虚构强度 |

转换只发生在请求控制副本，消息、工具参数、调用 ID、结果和输出预算保持不变。普通未接力调用保留原行为。遇到档位错误时，先核对调用端实际发送字段和目标元数据；不要用另一款模型或缩减历史来掩盖。完整规则见 [思考档位转换](docs/relay-reasoning.md)。

### 三类时间预算

| 层 | 作用 |
|---|---|
| 调用端 | DSH/Hermes/客户端首包、整轮、取消与重试 |
| 网关 HTTP | `server.requestTimeoutMs` 或精确路由 `modelRequestTimeouts` |
| 供给有效进展 | 默认约 30 秒无进展超时，正文/推理/工具增量刷新计时 |

HTTP 默认 180000ms，允许 1000–1200000ms。接力缓冲时可见首包较晚不等于上游没进展；OpenCode 这类完整回答桥自身有 120 秒生成期限；若启用接力，还要遵守供给无进展与剩余总预算，不能把桥接期限当成客户端和各层预算均已自动延长。连接/TLS、响应头、首个语义输出、持续生成空闲和整轮截止分别判断，SSE 心跳不等于生成进展。延长客户端超时不会修复认证、能力或额度错误，接力共用剩余总预算。详见 [可靠性说明](docs/reliability.md)。

```json
{
  "server": {
    "host": "127.0.0.1",
    "port": 19421,
    "requestTimeoutMs": 180000,
    "modelRequestTimeouts": { "UPSTREAM/MODEL": 600000 },
    "bodyLimitBytes": 67108864
  }
}
```

这是字段片段，不是完整配置。映射键精确匹配路由；改名同步改键。聊天正文默认 64 MiB，普通管理正文固定 4 MiB；WB 账号导入有独立 16 MiB 包装上限、原始文件合计仍 4 MiB。体积超限与模型上下文超限分开。见 [API](docs/api.md)。

## 每日签到与自动刷新

| 展示/状态 | 含义 |
|---|---|
| 每日签到领取 | 需要真实签到/领取，刷新余额不代替领取 |
| 今日签到额度已到账 | 同日有效官方账单确认；旧账单或正余额不算今日已领 |
| 官方每日自动额度 | 服务端自动重置，网关只观察 |
| 自动刷新 | 重新查询状态/余额，查询本身不加积分 |
| `success` | 按平台契约成功，结合回执与确认字段 |
| `already` | 此前已完成，不是又发一次 |
| `observed` | 观察到官方状态，不冒充主动领取 |
| `action_required` | 需要真实操作、登录或未接入执行器 |

排程含启动检查、每日时间、随机延迟与失败重试。幂等按稳定主体、任务、日期/活动窗口去重；HTTP 200 不代表每账号都领到了。完整状态见 [API](docs/api.md)。

### 自动签到的补偿与复核

- **逐账号、逐任务补偿**：临时读取/网络失败按 1、5、15、60 分钟退避，只重查未解决项；`scheduler.retryMinutes` 是普通重试间隔上限。平台明确返回的 `retryAt` 或等待时长优先，后台重启保留下一次重试时间。暂未开放的活动、设备当日占用、明确拒绝和需登录/交互的任务按较低频率复核，不把它们误当作当天全部完成。
- **启动与睡醒恢复**：启动批次也持久化逐项结果，避免随后立即重复整批；电脑睡眠、断网恢复后补查已到期任务。平台明确给出的领取窗口可先于普通排程触发，例如 Qoder 的每日 10:00 窗口；其他平台的常规定时不会因此被跳过。
- **提交与确认分开**：提交前写入 `preparing`，调用领取接口前原子标记 `submitted`，同时使用租约标识防止旧工作进程覆盖新回执。普通奖励接口只有明确停在提交前的中断才恢复写操作，旧版不明 `running` 和已提交超时只读对账；CodeArts 官方已领取待确认状态沿用专用确认流程。明确可重入的日常初始化仅白名单两项：小浣熊 `daily-quota` 的原生 GET 会话链、Loomy `daily-quota` 的幂等 `first-login`；宠物打工及其他奖励 POST 不在例外内。
- **短复核不重发**：领取后最多三次只读核验（立即、再等 0.3 秒、再等 1.2 秒）。响应丢失但官方已到账时自动闭环；官方仍未确认则保留待核验，后续由持久补偿继续对账。只有 `known:true` 且布尔 `claimed:true` 才记录签到成功。
- **凭据与展示不混淆**：WB 签到状态遇明确 401 时，仅尝试一次网关自有登录快照续期并重新读取官方状态；不重放领取 POST。本地“已处理”不再掩盖官方核验失败。Loomy 冷启动仅凭同主体、当日有效官方回执和新鲜余额恢复“每日额度已刷新”，不从余额为正推断签到完成。
- **原生登录更新立即复查**：CodeArts 登录失败退避期间，每 30 秒只读检查原生登录记录的内容版本。有效来源变化后，仅唤醒该失败任务；无关数据库更新不触发领取，读取失败不覆盖旧版本，官方明确要求的等待时间仍优先。
- **按平台执行真实日任务**：LobsterAI 的请求幂等键遵守官方 64 字符上限。小浣熊运行原生 `user_info → setting_info` 初始化，再以当日 `daily_grant` 账单延期确认，读取收入账单并有界分页；一次性桌面登录奖励不是每日签到，账单未完整读完不显示已知未完成。Loomy 只在当日日期、额度字段和新鲜余额匹配后核实登录额度，缺失或畸形回执继续补偿。
- **自动执行与此前已完成分开**：领取记录包含 `trigger / triggerSource`、`operationAttempted`、`automaticOperationConfirmed`、`automaticRewardConfirmed` 和 `benefitOutcome`。自动批次开始前官方已完成，只记 `available_before_run`，不算本次自动操作或新奖励。Loomy 的 `alreadyProcessed` 只用于区分 first-login 新处理／此前已处理，不单独证明每日积分新发放；小浣熊确认的是当日积分有效期延长，不是再发一笔积分。

- **本机身份读取恢复**：Qoder 原生身份 helper 的启动、超时、非零退出及响应格式故障归为本机临时不可用，由任务补偿重读，不误报为官方认证 401；不额外同步启动 helper、不返回过期身份。Trae 会跳过没有 `main.log` 的空日志会话；存在日志但身份仍在初始化时继续等待，不从历史记录任意选择设备。
- **登录态待恢复**：已保存 WB 快照缺少续期凭据、续期凭据被官方拒绝，或 CodeArts 要求重新登录时，先在对应客户端重新登录并更新网关保存的对应账号快照，再手动签到或等待后台补偿。刷新余额不代替重新登录，也不代替领取；错误项不计入签到成功。

每日签到、自动刷新额度、一次性免费计划和 WB 积分任务仍是不同类型；停用积分调用不关闭签到，官方未开放活动也不记为签到成功。后台需要持续运行，任务级补偿状态可在 `/admin/state` 的 `lastRun.tasks` 查看（`attempt`、`retryDue`、`nextClaimAt`、`reason`）。

### 如何确认是后台自动完成

“今日已完成”回答的是当前官方状态，不直接回答是谁完成。到“领取记录”核对本次回执：

| 字段 | 读法 |
|---|---|
| `trigger / triggerSource` | 区分手动调用与后台启动、定时、补偿、登录来源变化触发 |
| `operationAttempted` | 本次是否进入平台操作，而不只是查询已有状态 |
| `automaticOperationConfirmed` | 后台操作是否获得对应官方状态确认 |
| `automaticRewardConfirmed` | 是否另有本次自动新奖励证据；不能仅由余额为正推断 |
| `benefitOutcome=available_before_run` | 批次开始前已完成，手动或其他客户端完成均不会冒记为本次自动领取 |

小浣熊的自动日任务确认当日积分有效期延长，不是重复发放每日额度；Loomy 的 `newly_processed / already_processed` 只描述官方登录初始化，不能单独证明每日积分新到账。代码测试通过、GitHub CI 通过、官方已完成及真正自动新增权益，分别记录。

## 额度、用量与活动怎么看

这三个视图回答不同问题：**余额**说明账号目前有多少权益，**用量账本**说明经本网关发起过哪些尝试，**请求诊断台**帮助还原请求的组成与接力过程。

### 看一次调用：先筛选，再打开详情

从非 WB 平台余额卡进入详情，打开调用明细。选择日期范围，按实际模型 ID 和完成/失败/取消/进行中筛选，点 **刷新明细**。需要更早记录时点 **加载更多**；选中一行可读请求 ID、路由、实际账号/上游、尝试序号、普通或流式、工具标记、耗时、首字与用量。

**导出已加载明细**只把当前已经加载到表格的行保存为 CSV，不自动导出筛选范围内尚未加载的全部记录。想保留更多行，先加载更多再导出。WB 账号也可按管理 API 的 `accountId` 查询同一用量账本，字段与分页契约见 [用量说明](docs/usage.md)。

同一次客户端请求可能留下多次上游尝试。用 `requestId` 与 `attempt` 对照，不把接力后的最终成功当成所有失败尝试都没有消耗。`running` 也可能是进程异常后尚未收尾的历史记录，不等于请求还在正常输出。

### 数字旁边的来源比数字本身更重要

| 你看到的值 | 正确读法 |
|---|---|
| 上游输入/输出/缓存/推理 Token | 按上游明确返回计数；没返回就保持未知 |
| 积分或金额为 `null` / 未返回 | 没有精确扣费证据，不是免费或扣费为零 |
| 官方明确返回 `0` | 该字段的真实零值，与未知不同 |
| 两次余额核验差额 | 账号在这段时间的净变化，可能混合领取、到期及其他客户端消费 |
| 官方速率/日请求策略上限 | 政策或窗口观测，不当作账号此刻剩余 |
| 请求诊断台输入组成、字符估算 | 请求体积参考，不是官方计费 Token，也不证明客户端做过压缩 |

积分、现金、Token、次数、百分比和不同时间窗口各自展示，不跨单位相加。旧版本没有记录的历史和绕过网关的调用，不会被账本补造出来。

### 体检与正常调用分开看

模型体检按普通、流式、工具、回传分阶段保存结果、原因与时间；正常请求则按实际供给记账。体检使用独立来源，不让备用接力的成功覆盖被测平台失败。查看“全部通过”时还要看最近测试时间和账号/型号，旧结果不保证此刻额度、登录或上游服务仍然正常。

## 常用工作流

### 今天只想领取，再检查余额

点“全部账号签到” → 打开“领取记录”核对各账号结果 → 刷新余额 → WB 另到帐号池看今日签到和积分包。官方自动重置额度的平台会显示观察结果，不必反复点签到期待再次增加。

### 加一个 WB 账号，不改现有模型选择

添加登录、保存当前客户端账号或导入备份 → 核对版本/UID → 刷新身份与积分 → 修改名称/备注。所有开启中的同版账号池都会自动接纳新号，既有成员的先后次序保留；明确关闭的池和停用路由保持原样。需要新模型时再显式导入，不把账号添加当成已经发布模型。

### 一个模型不稳定，只做定向排查

保留客户端完整路由 ID → 查活动里的实际供给和错误 → 对选中模型做体检 → 按失败阶段处理登录、能力、容量、限流或额度。停用故障账号只影响它的候选资格；修复后重新核对，不靠循环全量测试或改成另一款模型。

### 执行 WB 任务后先离开，回来再核对

进入“积分任务” → 点“执行可自动任务” → 查看后台作业已受理 → 关闭窗口。回来重开窗口接管运行进度；若服务重启或作业已结束，先“重新查询”并读逐项回执。只想停止本批剩余动作时点停止按钮，不重复启动同一操作。

### 想优先用快到期积分，但不打断手头任务

保持轮换关闭 → 选国内/国际版与目标 → 保存策略 → 预览候选和排除原因 → 决定是否立即评估或启用周期轮换。网关目标影响后续请求；CLI 活跃时推迟。正在进行的回答、工具和上下文不迁移。

`data/` 指实际 `dataDir`，不保证在仓库。备份覆盖配置、整个数据目录和涉及的客户端登录/会话文件。活跃 SQLite 用一致性备份或停服务后复制，不能只复制主 DB 漏掉 WAL。

### 更新步骤

1. 记录版本、配置、实际 Node 与服务地址。
2. 停桌面/后端，备份程序、配置、数据并记录 SHA-256。
3. 拉取源码，运行 `npm ci` 与 `npm run check`，需要界面时重建 `desktop/build.ps1`。
4. 部署程序/后端，保留私有配置/数据，不用示例覆盖。
5. 核对 `/health`、主体、余额、启停路由和真实工具闭环。

更新前可用这张核对表确定备份是否完整：

- 实际启动入口、Node 和后端目录已找到；桌面默认配置、`--config` 或 `desktop.local.json` 覆盖已核对。
- 私有配置指向的实际 `dataDir`、密钥、数据库、账号快照都已包含；不是只保存 `config.example.json`。
- 涉及切号/会话迁移时，对应官方客户端文件和会话库也有原件；导出的 WB 账号文件不替代整个网关数据备份。
- 备份有 SHA-256，数据库可读；对活跃库使用一致性备份，或停止写入后复制。
- 更新后账号、路由启停、默认模型和用户新设置仍保持；需要 DSH 新模块时，再选择合适时机正常重载。

### 回滚步骤

先在独立副本验证旧程序及对应配置/数据，确认恢复旧行为再应用安装。恢复前再次备份当前状态，保留升级后新增历史；不要随意混配新旧 DB、配置与程序。

DSH profile 用 [DSH 回滚](docs/dsh.md) 和 `scripts/rollback-dsh.mjs`；删号、迁移、客户端模型同步分别用各自备份。删号不删聊天，所以账号配置回滚与聊天回滚不同。

恢复时先确定你要回退的是程序、账号凭据、配置、会话还是第三方客户端模型表。只恢复对应原件和引用，避免用旧整包覆盖升级后新增账号、聊天与路由。回滚成功要看旧行为和文件核验，不只看复制命令结束。

## 诊断与常见问题

### 健康正常，模型失败

`/health` 只说明服务运行。继续查认证、目录/导入、能力与真实调用，记录路由/错误码/普通或 SSE/工具阶段，以及失败发生在生成前、中还是回传后。

### 有积分却用不了

查详情的最近成功/失败与积分包，再看分类：`tools_not_supported`、上下文超限、401、429、`same_model_credits_exhausted` 分别是能力、容量、认证、限流与额度，不是一回事。

### 等很久才开始输出

核对接力完整响应缓冲、调用端重试和首包预算。请求诊断台可区分尝试与交付。有推理/正文/工具进展不按固定短时限杀掉；无进展、取消或整轮截止仍会终止。

### 新登录仍显示旧状态

用 `doctor` 核对官方主体与槽位绑定；新有效登录优先于旧缓存。换主体需明确重绑，不把两个主体历史静默合并；未知续期不重复使用旧旋转令牌。

### 封禁与认证拒绝混淆

所有保存账号包括停用/封禁项都保留。核对官方证据、本机标记、`auth_rejected` 和未知；401/403 不独立证明封禁。删号前核对 ID/UID。

### 汇总、积分包与任务不一致

核对时间、单位、全部分页与缓存；“已知积分”只统计有结果账号，未知不填零。过期包、奖励预告和当前余额不同；接受、执行、达标、领奖分别查回执，未接入执行器保留待操作。

### 413 / 上下文超限

413 是 `server.bodyLimitBytes` 字节上限，模型 Token 上限另查上游。网关不静默剪历史；调用端采用明确上下文管理策略或选择兼容供给。

### 401 / Host / Origin

模型面 `apiKey`、管理面 `adminKey`。Host/Origin 满足实际监听契约；远程监听、代理与客户端地址要一起配置。见 [API](docs/api.md)。

### 界面断连，请求仍运行

区分轮询、进程与模型长连接。先查健康、日志与请求状态，避免重复提交已受理的领取/删除/切号。GET 重连不重放写操作，手动暂停按用户操作恢复。

### 导入成功但账号仍然认证失败

导入说明交换文件已保存，不是一次官方续期或真实推理。先核对 UID、国内/国际版、到期时间与定向身份/余额查询；同主体凭据过期可重新授权或显式替换，不将认证拒绝误写为封禁。ZIP/JSON 错误在预览修正后再提交。

### 轮换开启却没有换账号

查看轮换预览与最近回执：当前已为目标、没有有效余额候选、冷却中、到期差异不够、积分调用暂停以及 CLI 存活都是不同原因。`gateway` 目标只影响下一次网关请求，原生客户端未换号符合该目标语义。正在输出的请求不为轮换而重放。

### 刷新后一直显示正在处理

账号操作成功、失败、取消与“操作已成功但刷新失败”有独立终态；按钮会恢复。界面更新以匹配的保存回执为准，HTTP 失败不乐观切换账号开关。反馈时给操作、终态文字与去密时间，不重复提交已受理的写操作。

### WB 任务窗口关闭了，为什么任务还在运行

关闭只结束本窗口等待。重开“积分任务”可接管仍在运行的作业；想停止后续动作要点“停止后续任务”或“停止整个批次”。如果显示“正在停止”，当前外部动作还待确认，先等回执，不连点执行。

### 重连或服务重启后，是否要重新点执行

先点“重新连接（只读）”找原作业；启动回执未知时不自动重发 POST。服务重启可能丢失内存句柄，但持久的待确认、领取和执行计划仍在。先重新查询官方状态，按逐项结果处理，别把“找不到作业”当成“上次没有发生”。

### 模型“导出”后为什么没有文件

“导出选中模型”是取消导入并停用路由，确认框已经列出语义。它保留目标和历史；到全部模型窗口重新勾选即可恢复发布。要保存 WB 账号文件，用帐号池的“导出账号”，这两个按钮操作不同对象。

### Windows 登录后没有自动运行

先确认已安装登录后自启任务，以及它引用的 Node、安装目录和配置仍存在。该任务只在当前用户登录后运行；它不保证关机、无人登录或网络不可用时领取成功。手动启动后查服务健康、日志、排程和逐账号结果，不只看任务已触发。

### 如何反馈

给版本、平台、客户端版本、路由、错误码、时间、请求模式、工具阶段与去密日志。不提交 token、Cookie、密钥、登录快照、个人 DB 或完整聊天。以错误分类和源码证据为准，不仅凭截图猜测。

## 测试、发布与贡献

```powershell
npm ci
npm run check
node --test tests/docs-contract.test.mjs
node --test tests/http.test.mjs
```

`npm run check` 构建 vendor 后执行完整离线回归，不对真实账号领奖。覆盖 OpenAI 普通/SSE/工具、取消、体积、鉴权、身份、池、额度/限流、账本、分页、任务、会话副本与文档。

文档契约检查必要章节、有效相对链接、API、完整致谢与凭据占位符，不用固定 README 行数代替完整性。Windows 构建在 Windows 验证；跨平台 CI 不代替真实登录或工具闭环。

### 真实验收与发布

按“基线 → 修改 → 独立副本回滚”记录命令、输入、输出、退出码、SHA 与行为。真实请求会使用账号额度，按目的分层测试；零余额或官方拒绝先保留状态，不循环发送付费生成。

正常提交/推送，保留历史与无关并发修改。发布前跑测试、链接/凭据检查；发布后核对远端提交、CI 与实际 Release 附件。本机安装、Git push、CI 与二进制发行分别验收。

- 新平台给来源/许可证、凭据形状、能力矩阵和离线测试。
- 改 API 同步调用方/文档；任务明确真实执行、达标与领奖回查，不伪造完成。
